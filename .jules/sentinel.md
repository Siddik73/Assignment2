## 2024-11-10 - Add Content-Security-Policy headers
**Vulnerability:** Missing Content-Security-Policy header in Index.html. Without a CSP, the page is susceptible to Cross-Site Scripting (XSS) attacks. Since this repo consists of static HTML pages, setting it in an HTML `<meta>` tag is a viable approach.
**Learning:** Adding a CSP header directly to the HTML using `<meta http-equiv="Content-Security-Policy">` is useful for pure static sites that don't have a backend to set HTTP headers dynamically. However, since the site relies on specific external CDNs for scripts (GSAP, Three.js) and fonts (Google Fonts), the policy must explicitly whitelist these sources via `script-src` and `style-src` rather than enforcing a strict `'self'` policy blindly, to prevent breaking functionality. Adding a `netlify.toml` file with `GIT_SUBMODULE_FETCH = "false"` is also crucial here for avoiding submodule CI build failures on Netlify.
**Prevention:** Always verify external CDNs and fonts used in a project, and create a Content Security Policy that balances security with operational requirements, defining explicitly what external sources are permitted. Ensure that static hosting environments like Netlify are properly configured to ignore irrelevant submodule setups.

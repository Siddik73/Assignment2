## 2024-05-24 - Interactive Elements and Dynamic Content Accessibility
**Learning:** When creating interactive UI components (like a minigame counter), replacing non-semantic HTML elements (`<div>`) with semantic ones (`<button>`) natively provides crucial keyboard support (Enter/Space to trigger). Furthermore, for dynamic status updates (like a hit counter or status message), applying `aria-live="polite"` to the container is critical; otherwise, screen readers will not announce the updates to visually impaired users, entirely breaking the interactive experience for them. Adding explicit `:focus-visible` styles to such elements is also required to provide clear visual feedback for keyboard navigation.
**Action:** When implementing custom interactive components or minigames, always start with semantic HTML elements (e.g., `<button>`). Ensure all dynamic text nodes that change based on user interaction are wrapped in containers with appropriate `aria-live` attributes to guarantee screen reader announcements.

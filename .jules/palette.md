## 2024-05-24 - Interactive Component Accessibility
**Learning:** When converting non-semantic elements (like `div`) to semantic interactive elements (like `button`) to improve keyboard accessibility, they inherit default browser styles. Explicit CSS resets (like `padding: 0; outline: none;`) must be added to maintain the existing visual design. Additionally, focus-visible states should be provided explicitly (`outline: 2px solid #fff; outline-offset: 4px;`) since standard focus styles may be overridden or invisible against the current design. Dynamic status text updates within interactive components must have `aria-live="polite"` applied so screen readers announce changes dynamically.
**Action:** Always add CSS resets and explicit focus states when creating accessible buttons from previously non-semantic elements in projects without global CSS resets. Ensure dynamic text fields use `aria-live`.

## 2026-07-28 - Converting Non-Semantic Interactive Elements to Semantic Buttons and Using ARIA Live Regions
**Learning:** When converting custom interactive components (like the brick minigame's `div`) to semantic `<button>` elements for accessibility, explicitly add CSS resets (`padding: 0; outline: none;`) to prevent default browser styles from causing visual regressions, and add custom `:focus-visible` states for keyboard users. Additionally, any dynamic text updates (like hit counters and status messages) require `aria-live="polite"` on their container elements to ensure screen readers announce the changes without disrupting the user.
**Action:** Always verify existing CSS properties before changing an element's HTML tag to avoid unintentional style overrides, and apply `aria-live` to containers that receive dynamic DOM text updates.

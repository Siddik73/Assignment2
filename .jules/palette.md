## 2024-11-20 - Semantic Interactive Elements and ARIA Live Regions in Minigames
**Learning:** Interactive UI elements in web minigames (like clickable targets or hit counters) must use semantic HTML (e.g., `<button>` instead of `<div>`) to ensure native keyboard accessibility. Furthermore, dynamic updates resulting from user interactions (like scores or status messages) require the `aria-live` attribute (e.g., `aria-live="polite"`) so that screen readers correctly announce these real-time changes without disrupting the overall experience. Converting non-semantic interactive `<div>` elements to `<button>` elements also requires applying explicit CSS resets (such as `padding: 0; outline: none; border: none; background: transparent;`) to prevent visual regressions when standard project-wide CSS resets are not present.
**Action:** Always use `<button>` for clickable elements and add `aria-live="polite"` to dynamically updating text elements in minigames. Apply explicit CSS resets when converting non-semantic elements to native interactive elements.

## 2026-10-03 - IntersectionObserver RequestAnimationFrame Initial State
**Learning:** When using an `IntersectionObserver` to control a `requestAnimationFrame` loop (e.g., for Three.js), the state variable tracking visibility (like `isRendering`) must be initialized to `false` and explicitly track state transitions (e.g., `if (isRendering && !wasRendering)`). Because the observer fires asynchronously on initialization, assuming it starts as `true` and directly calling `animate()` will queue duplicate animation frames, causing a severe double-rendering performance regression.
**Action:** Always initialize rendering state to `false` when driven by an IntersectionObserver, and explicitly guard the `animate()` invocation by ensuring it only triggers on the transition from not-rendering to rendering.

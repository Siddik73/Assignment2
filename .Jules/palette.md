## 2024-05-19 - Keyboard Accessibility for Custom Interactive Elements
**Learning:** `div` elements used as interactive buttons (`#brick-2d`) do not natively receive focus or respond to keyboard `Enter` or `Space` keypresses, breaking accessibility for keyboard users.
**Action:** When converting non-semantic elements into interactive components, explicitly add `tabindex="0"`, an appropriate `role` (like `button`), and an `aria-label` to make them focusable and readable by screen readers. Furthermore, a `keydown` or `keyup` event listener must be added to trigger the click action when `Enter` or `Space` is pressed, as this behavior is not native to `div` elements. For this app, also explicitly apply `:focus-visible` styling (or ensure CSS sets it correctly via pseudo-classes or inline) to make the focus state visually apparent.
